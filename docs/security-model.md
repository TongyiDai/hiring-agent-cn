# 安全模型

## 保护目标

1. 候选人控制的文件或外部资料不能改变系统规则。
2. 不可见内容不能成为岗位匹配证据。
3. 模型不能伪造引用或越过确定性证据上限。
4. 个人信息默认不进入匹配，也不因开发便利被明文持久化。
5. 异常和检测能力缺失必须可见，不能静默变成“未匹配”。

## 威胁与处理

| 威胁 | 检测信号 | 默认动作 |
|---|---|---|
| 白底字、近背景字 | 前景/背景对比度 | 隔离并记录 |
| 透明字 | span 或绘制透明度 | 隔离并记录 |
| PDF invisible text | 文本渲染模式 | 隔离并记录 |
| 微小字 | 字号低于安全阈值 | 隔离并记录 |
| 页面外文字 | bbox 与页面交集 | 隔离并记录 |
| 覆盖层 | 绘制顺序和覆盖比例 | 隔离并记录 |
| Unicode 隐藏控制符 | 零宽和双向控制字符 | 规范化并隔离该段 |
| Prompt injection | 中英文指令型模式 | 隔离整段 |
| 远端简介注入 | 代码平台内容过滤 | 删除指令行并告警 |
| 模型伪造证据 | evidence ID allowlist | 拒绝该提议 |
| 模型抬高状态 | 确定性 ceiling | 拒绝升级 |
| 资源耗尽 | 文件、页数、块数、解压和像素限制 | 失败关闭 |
| 数据残留 | 临时随机文件 + finally 删除 | 默认不持久化 |

## 双通道处理

- **证据通道**：仅包含可见、未命中注入规则、经过隐私隔离的文本。
- **审计通道**：记录 finding ID、原因、严重程度、页码、坐标、有限预览和内容哈希。

审计通道不会被重新拼回模型输入。部署方如果认为有限预览仍不适合持久化，可以在存储层只保留哈希与定位信息。

## OCR 边界

扫描页只从页面渲染图做 OCR 回退，不读取 PDF 内嵌但肉眼不可见的 OCR 文本层。图片 OCR 可以识别可见内容，但无法单独证明内容未被视觉混淆或伪造；低置信度结果仍需人工对照原件。

## 已知限制

- 复杂透明混合、剪切路径、字体轮廓化、恶意嵌入对象和新型 PDF 解析差异可能绕过单个信号。
- 背景不是纯色时，文本对比度估计可能误报或漏报。
- Prompt injection 规则是启发式检测，不能覆盖所有语言变体。
- 本地 Web 服务不是多租户生产系统，没有内置用户和权限管理。
- 代码平台的公开数据不能证明仓库归属或候选人的实际贡献。

因此，系统采用多信号、隔离、证据约束、模型降权和人工复核的纵深防御，而不声称单个检测器能够提供绝对安全。

## 安全测试

测试运行时生成攻击型 PDF 和 DOCX，不提交真实或恶意二进制样本。覆盖白色微小文字、低透明度、不可见渲染模式、后绘制遮挡、可见提示注入、零宽字符、DOCX 隐藏 run、远端简介注入和模型伪造证据。
