# 架构

## 核心判断

Hiring Agent CN 将“解析”“净化”“匹配”“模型解释”“人工签核”拆成相互约束的阶段。候选人控制的内容只有经过安全与隐私闸门后才能进入证据集合；模型没有直接读取原始文件、制造证据或执行招聘动作的权限。

```text
PDF / DOCX / 图片 / 文本
  │
  ├─ 文件资源限制
  ├─ 可见性检测与提示注入隔离
  ├─ OCR（仅从页面渲染图回退）
  └─ evidence_id + 页码 + 坐标
        │
        ├─ 身份与敏感字段隔离
        │
JD ── 合规提示 ── 招聘人员确认
        │
        └─ 确定性证据矩阵
              │
              ├─ 可选模型解释：只能维持或下调状态
              ├─ JSON / CSV / HTML
              └─ 人工逐条签核 → 新版本 + 审计记录
```

## 模块

| 模块 | 职责 | 关键边界 |
|---|---|---|
| `documents.py` | 读取 PDF、DOCX、文本和 OCR；建立证据块 | 不把原始文本层直接视为可信 |
| `security.py` | 可见性、控制字符和提示注入检测 | 命中后隔离，不进入后续文本 |
| `privacy.py` | 创建盲审副本 | 原值只保留哈希，不写入匹配输入 |
| `jobs.py` | 拆解 JD、提示公平招聘风险 | 招聘人员必须显式确认 |
| `matching.py` | 建立确定性证据候选与状态 | 没有证据只能是 `unverified` |
| `code_hosts.py` | 核验显式提供的公开代码链接 | HTTPS 域名白名单；未核验不参与判断 |
| `ai.py` | 可选模型解释和核验问题 | 不得升级状态或伪造 evidence ID |
| `human_review.py` | 人工逐条确认和版本化 | 不覆盖原报告，不执行 ATS 动作 |
| `render.py` | JSON、CSV、HTML | 报告始终显示边界和风险 |
| `web.py` | 本地页面和 API | 临时文件请求后删除，无自动淘汰端点 |

## 数据合同

所有主要结构都包含 `schema_version`。证据块使用内容哈希生成稳定 ID；审阅报告记录输入哈希、JD 哈希、引擎版本、策略版本、模型信息和人工签核 revision。

这使同一输入能够被回归比较，但不代表哈希可代替加密、权限或留存制度。

## 模型是可选的

默认确定性流程不调用模型。启用模型后，输入只包含经过净化的岗位要求和候选证据，输出还要经过结构和权限校验。模型的角色是改进解释与问题，不是决定候选人去留。

## 兼容上游

根目录旧 `score.py`、`pdf.py`、`github.py`、`roles/` 和 `prompts/` 暂时保留，便于追溯上游和渐进迁移。公开推荐入口只有 `hiring-agent-cn`。旧入口不具备本项目的完整安全保证。
